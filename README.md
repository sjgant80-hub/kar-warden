# Kar-Warden

**Live:** https://sjgant80-hub.github.io/kar-warden/

An integrity gate for AI components — with **no LLM judge**.

You write a component's **warrant**: the signed statement of what it's allowed to be — its baseline
config hash, the capabilities it may hold, the files it must carry, the named invariants that must
stay true. You present the component's **observed** state. Kar-Warden compares them deterministically
and returns a verdict:

- **INTACT** — the component matches its warrant.
- **DRIFTED** — only warn-level differences (a dropped capability, an undeclared extra file).
- **BREACHED** — at least one *severe* break: a changed config, an ungranted capability (privilege
  escalation), a missing declared file, a failed severe invariant. **One severe break is a breach and
  cannot be averaged away** by everything that still passes.

Everything runs in your browser. Nothing is uploaded.

## Why it matters

The estate's wedge is **provable, accountable AI**: an adversarial mutation proof of the *code*, and a
third-party **re-run** of the *result*. Kar-Warden is that wedge applied to component integrity — it
answers "did this AI component silently change or exceed its authority?" in a way anyone can reproduce.

## The three primitives (plus the receipt)

| function | what it does |
|---|---|
| `verifyIntegrity(warrant, observed)` | the core comparison → a full verdict naming exactly what broke |
| `monitorStatus(warrants, observations)` | a pure fold over many components → one StatusReport (worst status wins; a component that should have reported but didn't is `UNREPORTED`, never counted as fine) |
| `appendAnomaly(chain, entry)` / `verifyChain(chain)` | a hash-chained, tamper-evident anomaly log |
| `wardenReceipt(...)` / `verifyWardenReceipt(r)` | a portable receipt any third party **re-runs** — a verdict forged to say INTACT is caught even if its hash is recomputed |

## Proof-of-play

- **Unit tests:** `node --test kernel.test.mjs`
- **Mutation gate (witness):** 72/73 mutants killed, score **0.986**, 1 reviewed-equivalent (a SHA-256
  message-schedule loop bound whose extra iteration writes out of bounds on a fixed typed array — bit-identical,
  argued in `witness.baseline.json`). Run it yourself:
  ```
  node tools/witness.mjs mutate kernel.mjs --baseline witness.baseline.json --test node --test kernel.test.mjs
  ```
- **The live page IS the gated kernel:** `index.html` is generated by `make-page.mjs`, which inlines
  `kernel.mjs` verbatim. CI regenerates it and runs `git diff --exit-code index.html`, so the page can
  never drift from the proven code.

CI runs all three on GitHub's own runner on every push — the un-forgeable proof of the code; the live
page is the un-forgeable proof it's usable.
